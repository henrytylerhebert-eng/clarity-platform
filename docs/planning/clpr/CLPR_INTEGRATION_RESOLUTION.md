## Notes on package-internal issues found (informational, not blockers)

- The package's in-memory gateway (`InMemoryLearningPracticeGateway`) keys `observations`/`candidates`/`sessions` by bare id with no `organizationId` parameter on the read methods; tenant isolation is currently enforced one layer up, in `RecognitionService`'s `assertSameOrganization`/`assertOwner` calls after fetch, not at the gateway/query layer the rest of the codebase uses everywhere else (`case-repository`, `evidence-service`, etc. take `organizationId` as the first argument on every read). For a single-process, single-tenant-per-demo-session synthetic slice this is not exploitable today, but it diverges from house convention and from architecture invariant #7 ("tenancy in every predicate"). Recommend Codex add `organizationId` as an explicit parameter to `getObservation`, `getCandidate`, `getCandidateByObservation`, and `PracticeLabService.getSession`, filtering in the gateway itself, to match repo convention — flagged as a recommended adaptation, not a hard stop, since the outer service methods do already deny cross-org access.
- `implementation_package/validation/BUILD_VALIDATION.md` and `TEST_RESULTS.txt` describe the package's own standalone verification (34/34 checks against its own `tsc`/hand-rolled test runner). These are **not** evidence against the live repository's toolchain and should not be cited as proof of passing tests once integrated — Codex's own return package must report fresh results from the commands in §F.
