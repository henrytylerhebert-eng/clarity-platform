# Source Manifest and Trust Hierarchy

## Authority Order

1. Current working implementation under `app/`, `packages/`, `prisma/`, and tests.
2. Canonical architecture, workflow, governance, implementation-status, and ADR documentation.
3. Reporting Metrics Rebuilder definitions and blueprints.
4. Reverse-engineered workbook analysis as source/context.
5. Proposed design generated by ChatGPT.

If sources conflict, report the conflict. Do not silently select the most ambitious interpretation.

## Intentionally Excluded

- `reporting-metrics-rebuild-audit.xlsx`
- `formula_inventory.csv`
- `sheet_dependency_edges.csv`
- `sheet_summary.csv`
- Original hospital reporting workbook
- Any real patient data, credentials, secrets, or environment files

Reason: these are detailed source/audit or business-sensitive artifacts and are unnecessary for the first architecture/design pass. Request explicit owner approval before sharing them externally.

## Interpretation Rules

- `SCHEMA_BLUEPRINT.sql` is a reporting blueprint, not the transactional system of record.
- Workbook-derived formulas require operator validation.
- Existing frontend analytics events are a prototype seam, not a durable event platform.
- Product Studio is read-only and synthetic.
- Current role selection in the frontend is not production authorization.
- No measurements found means no outcome claim may be presented as established.
